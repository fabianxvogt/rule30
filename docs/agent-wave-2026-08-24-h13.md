# Agent wave — Rule 30 successor check at h=13 (2026-08-24)

## Result

The validated integer successor passed the exhaustive finite-width check through
`h=13`. For every width `h=0..13`, every encoded state was round-tripped through
the tuple representation, then checked against the tuple Rule 30 successor for
both boundary bits.

The exact totals are `16,383` state encodings and `32,766` boundary transitions:

```text
sum(2**h for h in range(14)) = 16,383
2 * 16,383 = 32,766
```

## Reproduction

Run from the repository root:

```text
$ PYTHONDONTWRITEBYTECODE=1 /usr/bin/time -p python3 experiments/bitwise_successor_check.py --max-horizon 13
PASS: h=0..13, 16383 state encodings and 32766 boundary transitions checked
real 0.17
user 0.14
sys 0.01
```

The `--max-horizon` option makes the h=13 bound directly reproducible while the
default remains h=12. Output is one bounded summary line; a mismatch raises an
`AssertionError` identifying its width, state, boundary bit, actual result, and
tuple-reference result.

## Interpretation and limits

**EMPIRICAL / INCREMENTAL.** This is an implementation check of the integer
encoding and successor against the tuple reference at finite widths. It does not
change any theorem claim and does not prove the successor identity at widths
above `h=13`, infinite Rule 30 behavior, center-column non-periodicity, or any
other statement about the open center-column problem.
